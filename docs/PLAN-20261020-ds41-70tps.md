# DS41 decode to 70 tok/s on 2 x RTX 3090 (plan, 10-20)

Model: DeepSeek-V4.1-Flash-1017 PAW X3.1 (256 kept experts, `20261019_truss_port/data/pack`). Earlier plan:
`PLAN-20261019-ds41-speed.md` (its tables and D-items stay valid; this file is the path from today's measured state).
User (10-20): "27b dense got 40-50, this only 16b active so 70 tok/s is easy, it even uses 2 GPUs and they are idle
most of the time"; engine changes are allowed if the code stays clean, structured and documented; executor = opencode
(v1 TUI, tmux `ds41exec`); when stuck, research instead of concluding "impossible".

## 1. Where a decode step goes today (measured)

Best plain setup (TRACKER #206): split 14 on GPUs 0 + 2, CPU trellis tier (20 threads, pinned), weight skip 0.12,
`TRUSS_AUX_CPUS=auto`, PCIe share 0.1, adaptive tier: **26-29 tok/s** (35-38 ms per word, spikes from the renters'
llama-server threads, ~5.5 cores). Best with the drafter (#207): DSpark 3 drafts, PCIe share 0, hints off:
**29.8 tok/s** (27.8 / 32.0).

nsys of the plain step (42.8 ms, `logs/e10_nsys2`):

| part | ms / word | note |
|---|---|---|
| dense Q8 gemv (attention projections, shared expert, hc) | 10.3 | ~7.6 GB of Q8 per word at ~750 GB/s |
| routed experts on the GPUs (window kernel) | 5.4 | |
| other GPU kernels (norms, routing, attention, mHC) | ~5.7 | attention itself 0.4 |
| **GPU waits for the CPU's expert results (`spin`)** | **11.0** | ~65 missed experts per word on the CPU |
| GPU waits for the expert plan (`wait_plan`) | 5.2 | |
| gaps; the two GPUs take turns (layer split) | ~5 | each GPU idle ~50-60% |

Bytes per word: ~7.6 GB dense Q8 + ~2.5 GB experts ~= PAW-27B dense (~10 GB), which tqLLM decodes at 35.7 tok/s
without a drafter and 114-116 with DFlash2 on ONE 3090 (`~/tqllm/docs/X3_STATUS.md`). 70 tok/s = **14 ms per word**.

## 3. Phases (one executor brief each; a phase starts when the previous gate is read)

### A. Weight-share skip threshold (planner, running: `data/e12_skip.sh`)
Speed for F = 0.12 / 0.2 / 0.3 / 0.4 and decode-path KL (`ds41_kl`, `TRUSS_KL_DECODE=768`, 8 x 256) each.
Gate: the largest F within the KL noise of 0.12 (±0.006, #200) becomes the default candidate.

### B. Trellis dense matrices in `blocks::Linear` (E13)
`src/blocks/linear.h` names trellis dense as "the next format", never built. Port tqLLM's X3 dense kernels, the
most advanced trellis kernels we have (`~/tqllm/kernels/formats/x3/`: `gemv_window.cu` n = 1..16 window GEMV with
bit-identical columns for every n, `reconstruct.cu` straight to int8 with load-time row scales, `codec_mul1.cuh`,
`had128.cuh`, `window.hpp`), as a model-agnostic Linear format: tensors `<name>.m3_trellis` / `m3_meta` /
`m3_suh` / `m3_svh` (the expert overlay's naming), decode rows via the window GEMV, prompt rows via reconstruct
to int8 + the existing int8 GEMM. Gates: kernel parity vs tqLLM on real PAW-27B-X3.1 matrices
(`~/tqllm/models/PAW-27B-X3.1.gguf`); per-shape times within 5% of tqLLM's table (X3_STATUS "Phase T1/T2");
golden 7/7 IDENTICAL (Q8 paths untouched); docs; files < 500 lines.

### C. Encode DS41's dense weights to X3.1 (E14)
Which matrices: attention q_a, q_b, kv, wo_a (grouped), wo_b, indexer q_b, shared expert gate / up / down (the
7.6 GB that every word reads; norms, routers, hc, sinks stay F32; embedding / head stay Q8 first). Calibration =
the PAW-27B recipe (`~/ML_projects/paw27b/README.md`, `20260923_x3up`: encoder; corpus as `20261018_poc`'s code
captures), Hessians from the dsref reference (`20261018_poc/scripts/a2_capture.py` pattern) on GPU 0 / 2 under the
watcher. Target K3.5 (~3.5 bpw, PAW-27B-X3.1's rate) -> ~3.4 GB instead of 7.6. Pack tool `tools/tk-pack/
ds41_dense_x3.py` (an overlay on `ds41-dense.gguf`, like the experts). Gates: `ds41_kl` vs the Q8 pack (budget: KL
+0.01 at most, else K4 for the sensitive matrices); decode tok/s; resident experts gained.

### D. Re-plan the expert budget and measure (E15)
With ~4 GB freed per pair of stages: residency, CPU misses per word, plain and DSpark (3 drafts, PCIe-free)
tok/s, prefill. Pick the split point again (14 / 20) for the new byte balance.

### E. Both GPUs on every word (E16; design first, engine change)
After C the remaining GPU time is ~10-12 ms in turns. Options to measure on paper with the nsys numbers before
code: (a) dense TP2 (each GPU half the rows of every dense matrix; 2 syncs per layer through mapped host memory as
mmnga does); (b) expert parallelism (both GPUs hold experts of every layer, each computes its own, summed;
dsx's GPU1-as-expert-server layout); (c) Strata `--pipeline-windows 2` for verify passes (#151: +16% GPU-bound).
Design note -> user review -> implement the winner as a general engine feature.

### F. Drafting on the new base (E17)
DSpark 3 / 4 / 5 drafts PCIe-free; the confidence head stop (SSHdotCodes pro6000: draft only while a row pays);
retrieval drafts (tqLLM `--draft-retrieve`, D11) for code-agent text; verify-window exactness (mmnga N32:
serial vs batch8 bit-identical) so spec == plain.

## 4. Execution rules (every brief)
- Executor: opencode v1 TUI (`~/.opencode/bin/opencode --auto -m opencode/deepseek-v4.1-flash-free`) in tmux
  `ds41exec`; brief `20261019_truss_port/exec/E<n>_brief.md`, report `E<n>_report.md` ending with EXECUTOR-DONE;
  the planner reviews, runs gates it doubts, commits, writes TRACKER rows and this file's status.
- GPUs 0 / 2 only (`scripts/free_gpu.sh`), every GPU job detached (`setsid --fork nohup run_watched*.sh ...`),
  waits on events (`scripts/wait_log.sh`), never `sleep` loops. GPUs 1 / 3 are the renter's.
- Before any step: TRACKER rows + lessons for the area, then tqLLM / Strata / mmnga / GitHub. Stuck: research and
  write what was tried; "impossible" is not a result.
- Quality only by `ds41_kl` or exact math. Golden 7/7 for shared code. Docs with the code. Files < 500 lines.
