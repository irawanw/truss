# Plan: decode 100 tok/s, prefill 3,000 tok/s (written 2026-10-02)

The working plan for the next targets (user goal order: decode 150 → prefill 3,000 → decode 200 → prefill 4,000;
first milestone **decode ≥ 100 tok/s**, then **prefill ≥ 3,000 tok/s** on the 3,398-token code prompt). Every step
below targets a gap that has already been measured. Do not add steps that are not backed by a measurement; if a
step misses its gate, the next action comes from that step's profile, not from trying settings.

Sources: Strata v0.1.31 profile on this box (`~/ML_projects/flashnext/20261001_strata_profile/reports/STRATA_PROFILE.md`,
logs `data/logs/c9400.log`, `static13975.log`), TRUSS best run TRACKER #79 (`f22p_2`: share 0.2 + hints 4 + 22
pinned threads + Strata profile, `TRUSS_PROFILE_SECTIONS=1`).

## Fixed rules

- **Error must stay below Strata's. No lower-bpw pack.** The codec may change only to become cheaper to run at
  equal or lower error.
- Don't blame the codec, hardware or CPU: if our kernel costs more per expert than Strata's, make it cost the same.
- GPU 2 only (0, 1, 3 are in use by others); stop if a renter takes GPU 2. Host RAM: TRUSS ≤ 40-45 GB (record peak RSS).
- Each step: 3 interleaved repeats, 256 tokens, same prompt (`prompt_code4k.i32`); judge by the per-section device
  times (steadier under renter load than tok/s); TRACKER row + docs in the same commit.

## 1. Where the time goes (measured)

Best TRUSS run: 77.0 tok/s, 2.53 tokens/pass, **33.0 ms/pass** (device 32.05). Strata column: 9,400 static slots
(same residency as ours), request 2, 2.59 tokens/window, 22.5 ms/window, 114.9 tok/s.

| GPU expert kernel (VRAM hits) | 4.51 | 3.36 | 1.2 |

| **pass / tok/s** | **33.0 / 77** | **22.5 / 115** | |

- 100 tok/s at 2.53 tokens/pass needs **≤ 25.3 ms/pass** (−8 ms). The measured gaps sum to 11-14 ms → ~22 ms *(est.)*.
- Root cause of the two largest rows: **CPU thread time per expert in the engine is 1.56 ms** (items sum 140.7
  ms / 90.1 experts per pass) vs **Strata 0.84 ms** and our own unit test 0.68 (single) / 0.75 (pool). Because the
  CPU tier is slow we push 20% of misses over PCIe (the 3.15 ms copy wait); Strata pushes ~0.
- Open correctness item: with the CPU tier, spec output equals plain greedy on only 22/256 tokens (CPU fp32 vs GPU
  fp16 activations round differently, and which tier computes an expert depends on the cache state).

**Plan changes from D0** (measured causes replace the D1/D4 guesses):
- **D1 (CPU tier):** input-split items (each item preps its own 128-input Hadamard blocks, so no serial prep step;
  contiguous reads, -21% item time), partials summed in fixed item order, silu at the gate/up -> down flip.
  Gate: 2-expert call <= 0.12 ms (now 0.21) in `pool_probe`, then in the engine.
- **D1b (kernel):** our kernel's ALU cost per weight (2.8 cycles / 8 weights) is 2x Strata's per expert; next CPU
  lever after the split.
- **D4 (non-MoE):** first (i) PLE rows read asynchronously and in parallel, issued when the window's tokens are
  known, collected at the PLE layer, row + scale in one read, plus a row cache (Strata's `ple_reader`); then
  (ii) one CUDA graph per window size (needs D2: no per-layer copy API calls).
