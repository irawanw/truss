## 5. The self-iteration pipeline (PAW DS41 iterates its own engine)

Roles: **planner** = Claude (this file, briefs, reviews, merges, promotion); **executor** = PAW DS41 itself through
**oh-my-pi** (`omp --model ds41/ds41-flash --auto-approve`, tmux session `ds41paw`, cwd `~/trellis-kernel`).

- **Two checkouts.** `~/trellis-serve` (branch `served`) is what pm2 `truss-ds41` runs: the executor's own model.
  Only the planner moves it (`git -C ~/trellis-serve merge --ff-only master`, rebuild its `build-dsv41`, restart)
  after golden 7/7 + bench health PASS. The executor edits and builds only `~/trellis-kernel` (branch per brief).
  A broken dev build can never take the executor's model down.
- **GPU jobs** (bench, golden, nsys) go through `scripts/ds41_gpu_job.sh`: it stops the served model, runs the job
  under the renter watchdog and returns only when the model answers again. The executor runs them in the
  FOREGROUND with a tool timeout of 900 s (bench ~4 min + ~1 min restart; golden ~5 min + restart).
- **Loop per brief**: brief `20261019_truss_port/exec/E<n>_brief.md` -> executor measures (`scripts/bench_ds41.sh`),
  changes code, `ninja`, unit tests, `scripts/golden_ds41.sh` when shared code changed, bench again, writes
  `E<n>_report.md` (numbers, arms table, golden result, files) ending with the line `EXECUTOR-DONE` -> planner
  reviews and re-runs what it doubts, commits, TRACKER row, promotes.
- **Rules the executor follows**: GPUs 0 and 2 only and only via the scripts above; GPUs 1 / 3 are the renter's
  (never touch); no `sleep` polling; quality only by `ds41_kl` (`--kl-seqs 8`) or exact math; health FAIL = stop
  and report; files < 500 lines; docs with code; golden 7/7 for shared code; never delete data, never `pm2 save`,
  never touch `~/trellis-serve`.
