## Phase L: the loop's cause (3.5 h)

Hypotheses beyond "KL is higher". Each one is an arm in `tools/tk-bench/arms_loop.py` (real looping prompts from
`req_log`, k samples per arm, loop = the server's guard), same prompts, interleaved:

| id | hypothesis | arm / measurement |
|---|---|---|
| L1 | KL is measured at 1,024 tokens of context only; at 20-60K the skip may cost far more | KL / top-1 of skip 0.20 vs skip 0 **at 32K and 64K** (self-reference: skip 0, same pack; no FP4 reference that long) |
| L2 | the expert skip is decided per call, so a verify window (3 drafts) skips different experts than one-token steps: speculation changes the distribution | loop rate spec on vs `spec=0`; KL of verify-row logits vs one-token logits on the same tokens |
| L3 | the n-gram (Engram) tables are int4 and keyed by the last tokens: a repeated n-gram re-injects the same row, a feedback loop | arm with the Engram rows' scale x0 / exact rows for the hit n-grams; loop rate |
| L4 | sampling path: min_p 0.05 + temperature 1.0 in the sampled verify, the end-of-turn ban, the new word penalty | loop rate per sampling arm; check `spec_accept` keeps the distribution (chi-square on a fixed prefix) |
| L5 | tail prefill (consumer layers read only the last 134 rows) or the compressed-KV path drifts at long context | arm tail prefill off; recall is 100%, but recall is copying, not reasoning |
| L6 | the prompt: reasoning-effort mapping (xhigh -> max), dropped history reasoning, omp's injected notices | replay with effort high vs max; the official DeepInfer encoder output vs ours, byte for byte |

References read for this (pulled 10-22, see below): Maya `tools/maya_quant/loop_test.py` (a loop-rate test with
three.js / canvas prompts, the shape that looped here), Strata `serve/server.py` loop recovery (12-word passages seen
3x over 25% of the last 2,000 words; tail period <= 64 chars), TensorFold `--loop-guard` (short cycle or a >= 1,024-
token verbatim passage). None of them names a cause; they all guard.

Gate L: a hypothesis is the cause only if switching it off cuts the loop rate at skip 0.20 to the skip-0.10 rate or
below, on >= 24 samples. Then fix it, and serve skip 0.20 if its loop rate <= skip 0.10's.

## Phase B: no idle between the GPUs (5.5 h)

First a trace on x16 (nsys, served config, 36K, skip 0.20) to get today's idle split per GPU, then the levers, biggest
expected first:

| id | lever | what it removes |
|---|---|---|
| B1 | **pipelined verify windows** (Strata `--pipeline-windows 2`): while the last stage verifies window k, the first stage runs window k+1 on the drafter's guess; a rejected guess is thrown away | the first stage's idle (~2/3 of a pass on GPU 2 in #226) |
| B2 | **PCIe share retuned for x16**: `TRUSS_PCIE_FRAC` 0.1 was set on x8 (13 GB/s); x16 measures 27 GB/s: more misses fetched, fewer computed on the CPU | the spin on the CPU tier (27 ms/pass) |
| B3 | **GPU work during the CPU-tier wait**: start the next layer's attention / shared expert / the drafter while the CPU computes the routed misses | spin |
| B4 | prefill: the second stage idles while the first streams cold experts; balance the split for prefill or let the idle card fetch the next chunk's experts | prefill idle |

Gate B: decode tok/s at 36K and 150K, interleaved A/B (`scripts/bench_ds41.sh`), golden 7/7, KL unchanged where exact.

## Phase G: 4 GPUs (1 h, running)

middle stages hold 1,536 each and reserve 4 GB prompt buffers they do not need -> fix the budget split, then bench.
Answer: decode/prefill vs 2 GPUs and the idle per GPU.
